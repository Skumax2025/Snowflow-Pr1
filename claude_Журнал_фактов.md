# Журнал фактов

## Суть
Журнал фактов — сырой лог всего, что происходит в симулируемом мире: кто, что, где и когда сделал, независимо от того, узнает об этом игрок или нет. Он не оценивает и не решает, кто мог это услышать, — только фиксирует факт. Это единственный источник, с которым можно сверить слова игрока ([[Парсер]]), из которого можно породить радиосигнал ([[Генератор эфира]]) и собрать причину произошедшего для [[Газета|Газеты]]. Без него не работает ни один из трёх.

## Как работает
1. Сущность Мира (Город, Структура, Фракция, Конвой) через свой [[Пулы событий|Пул событий]] при срабатывании события вызывает запись в Журнал — один вызов на одно событие. Кризисные ветки [[Режиссёр]]а пишут напрямую тем же контрактом записи.
2. Запись плоская, один и тот же формат для всех типов событий (см. Данные). Никакой обработки на этом шаге: источник просто фиксирует факт, ничего не считает про то, кто мог его услышать.
3. **Ретеншн: весь Журнал хранится всю партию, ничего не чистится.** 12–15 дней — смешной объём, а скользящее окно сломало бы шторм-алиби по старым меткам времени и дайджест [[Газета|Газеты]] за пропущенные дни. TTL в проекте есть только у сигнала, и живёт он у [[Генератор эфира]]. **[решено, аудит]**
4. Четыре системы читают Журнал каждая своим запросом, ничего в нём не меняя:
   - **[[Генератор эфира]]** на такте генерации берёт записи за окно времени + отдельно читает текущее состояние Ретрансляторов, Постов и Баз — и сам решает, кто мог наблюдать событие и стоит ли о нём вещать. Видимость нигде не хранится, её всегда считают заново.
   - **[[Парсер]]** получает claims игрока и ищет совпадающие записи по (субъект, место, время) — выносит вердикт: правда / ложь / неточность.
   - **[[Газета]]** в свой час забирает агрегатные записи «рапорт обработан» и записи, не привязанные ни к одному claim, чтобы объяснить причину того, что случилось без игрока.
   - **[[Фракции]]** читают только поле «место» свежих записей, чтобы выбрать квадрант атаки.
   Плюс [[Финал]] и [[Мостик]] точечно ищут факт «город мёртв», а [[Стенд симуляции]] делает выборку по всему прогону для метрик.
5. [[Погода]] в Журнал не пишет. История штормов по квадрантам ведётся отдельно, это часть заметки [[Погода]] и хранится там тоже всю партию.
6. В Журнал не попадают: вердикты [[Парсер]]а (это мнение о рапорте, а не факт мира), фантомные сигналы и голоса [[Галлюцинации|Галлюцинаций]] (они выдуманы), офтопик-тексты. Единственное исключение из «только симуляция» — агрегатная запись «рапорт обработан», которую пишет [[Город]]: это факт того, что город обработал донесение, а не оценка его правдивости.
7. [[Карта]] Журнал не читает никогда — осознанная изоляция.

## Контракт
- **Вход:** события от Пулов событий любой сущности Мира и от кризисных веток [[Режиссёр]]а. Каждое — готовая запись (см. Данные), источник ничего не обязан знать о видимости, дальности связи или диапазонах.
- **Выход:** выборки записей по фильтрам (окно времени, место/квадрант, субъект, тип события, тег). Никаких вердиктов и оценок — только сырые факты.
- **Владеет:** единолично списком всех фактов мира за партию.
- **Не знает:** о видимости и дальности радиосвязи, о состоянии Города, о том, что написал игрок, о погоде.

## Данные

| Поле | Тип / диапазон | Комментарий |
| :--- | :--- | :--- |
| id | строка/число, уникален | — |
| время | метка времени партии | момент события |
| тип_события | перечисление | [нужно значение] — полный список типов собирается по мере наполнения пулов |
| субъект | ссылка на сущность Мира | кто именно (Склад №4, Конвой №7, Фракция:Противники...) |
| место | квадрант, буква+цифра | формат канонизирован в [[Погода]]; **обязателен для всех источников**, включая Фракции и Режиссёра — иначе запись нечем озвучить |
| статус | строка/перечисление | «в пути», «уничтожен», «прибыл»... [нужно значение] полный список |
| участники | список ссылок на сущности | [нужно значение] — формат не решён |
| тег_архетипа | перечисление, может быть пуст | сейчас единственное значение — «агрессивное». Хранится **явным полем**, а не выводится [[Генератор эфира]]ом из пары (тип_события, тип субъекта): скрытая таблица соответствий — то, что агент реализует по-своему. **[решено, аудит]** |

Видимость сюда сознательно не входит — решает [[Генератор эфира]] на лету, не Журнал.

## Первый срез
Склад порождает одно событие «конвой вышел» → Журнал принимает и хранит запись → [[Генератор эфира]] умеет прочитать её выборкой за последний час (пока без реального радиосигнала, можно в лог). Отдельно: запись с тегом «агрессивное» находится выборкой по тегу.

Признак готовности: запись, сделанная Складом, находится в выборке Журнала по фильтру времени, субъекта и тега.

## Связи
- [[Пулы событий]] — шлёт событие: каждая сущность Мира через свой пул пишет факт, включая дочерние сущности вроде Конвоя.
- [[Режиссёр]] — шлёт факт напрямую из кризисной ветки «информационная_атака».
- [[Генератор эфира]] — читает: факты + отдельно состояние Ретрансляторов/Постов/Баз, сам считает видимость.
- [[Парсер]] — читает: сверяет claims игрока с фактами, выносит вердикт.
- [[Газета]] — читает: агрегатные записи Города и факты без привязки к claims.
- [[Фракции]] — читает: только поле «место» свежих записей, для выбора квадранта атаки.
- [[Город]] — пишет факты своего пула и агрегатную запись «рапорт обработан».
- [[Финал]], [[Мостик]] — читают точечно: факт «город мёртв».
- [[Стенд симуляции]] — читает: полную выборку прогона для метрик.

## Открытые вопросы
- Полный список типов событий — соберётся по мере наполнения пулов.
- Формат поля «участники» — список чего именно.
- Понадобятся ли теги архетипа помимо «агрессивного» — сейчас поле есть, значение одно.
