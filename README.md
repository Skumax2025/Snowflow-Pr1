# Snowflow

Ты — радист на вышке у города, затерянного в снегах. Ты слышишь эфир: обрывки
передач на разных диапазонах, часть правдивых, часть искажённых, часть — прямая
ложь мародёров. Ты тратишь топливо на проверку сигналов, отделяешь правду от
лжи, наносишь всё на карту руками и каждый вечер отправляешь в город сводку.
Город реагирует на то, что ты написал, а не на то, что произошло. Победы не
существует.

Реализация по ГДД: мастер-концепт `Snowflow___мастер-концепт.md` и 26 заметок
разделов (`claude_*.md`). Файлы ГДД — только для чтения, код им подчиняется.

## Команды

```bash
npm install      # один раз
npm run dev      # локальный запуск игры (http://localhost:5173)
npm test         # все тесты одной командой
npm run sim      # Стенд симуляции: 100 headless-прогонов
npm run build    # типы + сборка в dist/
```

Флаги Стенда: `npm run sim -- --runs=100 --seed=20260817 --days=13 --json`,
плюс отладочные `--isolated` (режим «изолированный Город») и `--reports`
(синтетический поток рапортов).

Серия печатает и метрику эфира: сколько сигналов родилось за прогон, сколько
их живёт в эфире в среднем, какую долю партии эфир пуст и как плотность
меняется по дням.

## Стек

| Роль | Выбор | Почему |
| :--- | :--- | :--- |
| Язык | TypeScript 5, строгий режим | требование ГДД |
| Рантайм | Node.js 22, ES-модули | — |
| Сборщик и dev-сервер | Vite | работает из коробки, одна команда |
| Тесты | Vitest | тот же конфиг, что у Vite, нативный TS |
| Функции | Vercel Functions (`api/`) | бэкенд назван в ГДД |
| LLM | Gemini через REST, только в серверной функции | ключ никогда не в браузере |

Продакшн-зависимостей нет. ГСЧ, шина событий и валидатор JSON-схемы написаны
руками — по два-три десятка строк каждый.

## Структура

```
src/core/     ядро: headless, ни одного упоминания DOM
src/config/   все числа, веса, таблицы событий и шаблоны фраз
src/sim/      Стенд симуляции
src/ui/       интерфейс: только читает состояние и шлёт команды
api/          serverless: прокси к Gemini, База аномалий, проверка связи
tools/        плагин Vite, поднимающий api/ в режиме разработки
tests/        «Первые срезы» заметок один к одному
```

## Как идёт время

Время течёт само: 3 игровые минуты за полсекунды реального времени, то есть
сутки укладываются примерно в 4 реальные минуты, а партия в 13 дней — в 52.
В панели «Вахта» есть пауза и множители ×1/×2/×4: пауза нужна, чтобы читать
газету и переносить сводку на карту, не теряя вахту.

Часы живут в интерфейсе и шлют ядру ровно то же событие «потратить N минут»,
которое шлют действия игрока. Ядро по-прежнему само себя не тикает.

## Архитектурные инварианты

Проверяются автоматически в `tests/architecture.test.ts`:

- ядро headless — симуляция не знает о UI, DOM и рендере;
- данные вне логики — числа и таблицы только в `src/config`;
- единый источник случайности — `Math.random()` не вызывается нигде, ГСЧ
  инжектируется и инициализируется сидом, один сид даёт побитово идентичный
  прогон;
- единый рантайм-луп — системы не запускают себя сами, их тикает Игровой цикл;
- ключ к LLM только в переменных окружения serverless-функции;
- деградированный режим обязателен: отказ, таймаут, лимит или невалидный JSON
  от внешнего API не меняют характеристики и не ломают партию.

## Ключ Gemini и проверка связи

Ключ нужен только серверной функции; для игры, сборки и тестов он необязателен.

Локально положи его в `.env.local` в корне проекта:

```
GEMINI_API_KEY=...
```

`npm run dev` поднимает каталог `api/` собственным плагином и читает этот файл;
на Vercel то же самое делает платформа, ключ живёт в переменных окружения
проекта. В браузерный бандл он не попадает никогда.

Проверить, работает ли ключ, можно прямо в игре: панель «Связь с Gemini»,
кнопка «Проверить связь». Она делает самый дешёвый настоящий вызов той же
моделью, которой пользуется Прокси, и переводит ответ в понятную причину —
ключ не задан, отвергнут, модель недоступна, квота исчерпана, таймаут.
Это нужно именно потому, что деградация по построению неотличима от успеха:
без диагностики партия молча идёт на пустом разборе.

Без ключа Прокси отдаёт синтетический пустой разбор — по форме неотличимый от
настоящего ответа. Сборка и все тесты проходят без ключа и без сети.
