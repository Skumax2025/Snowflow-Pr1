# Пулы событий

## Суть
Единый механизм, которым живёт весь симулятивный Мир. Любая сущность Мира — Город, Структура (Пост / База / Склад / Ретранслятор), Фракция, а также сущности, порождённые в ходе игры (Конвой), — устроена одинаково: набор характеристик плюс пул возможных событий, где вес каждого события зависит от текущих значений характеристик. Добавить новый тип сущности или новое событие — значит дописать строки в таблицу, а не написать код. Без этого механизма [[Журнал фактов]] нечем наполнять, а Мир не живёт без игрока.

## Как работает
1. Каждая сущность Мира владеет собственным пулом — таблицей событий с базовым весом, модификаторами по характеристикам и эффектом (см. Данные).
2. У каждого типа сущности свой тик — интервал, с которым она катает свой пул. Тик не хранится во [[Время]]: пул сам сверяет текущий момент партии (читает его у [[Время]]) со своим расписанием. Вызывает эту сверку [[Игровой цикл]] на каждом шаге лупа — включая шаги, которыми он прогоняет перемотку сном.
3. На тике сущность считает вес каждого события пула по формуле «базовый вес + модификаторы от своих текущих характеристик» [нужно значение — точный вид формулы], включая опцию «ничего не произошло», и катает взвешенный случайный выбор из **переданного снаружи источника случайности** (см. п.9).
4. Если событие выбрано:
   - применяет эффект к своим же характеристикам, если он есть (эффект может быть пустым);
   - пишет факт в [[Журнал фактов]] по контракту записи, обязательно заполняя поле «место» и, если событие помечено, поле «тег_архетипа»; сущность собирает запись из шаблона события, ничего не решая про видимость или диапазоны;
   - если по правилу изоляции нужно уведомить другую сущность — шлёт ей явное событие, не трогая её характеристики напрямую. Пример: Конвой, дойдя до терминального исхода, шлёт **Городу напрямую** «поставка_доставлена» или «поставка_потеряна» — не через Склад-родителя.
5. Событие может быть помечено как порождающее дочернюю сущность. Тогда вместо (или вместе с) эффектом на себя сущность создаёт новую сущность того же общего вида (характеристики + пул), которая дальше живёт и тикает независимо. Пример: у Склада в пуле есть событие «родить конвой».
6. С момента рождения дочерняя сущность тикает свой пул независимо и по тому же общему механизму (шаги 2–4). Родитель её не тикает и не решает за неё, что произойдёт дальше — только хранит список, кто из детей ещё жив.
7. У дочерней сущности есть терминальные события (у Конвоя — «прибыл», «перехвачен», «погиб в шторме»). Терминальное событие пишет финальный факт в Журнал, шлёт явное событие адресату и удаляет сущность из реестра родителя. После этого сущность больше не тикает.
8. Правило слышимости (звучит ли событие в эфире, на каком диапазоне) пул не решает — это работа [[Генератор эфира]]. Пул только гарантирует, что факт в Журнале появился и что у него заполнено «место»: без координаты запись нечем озвучить.
9. **Источник случайности приходит снаружи. [решено, аудит]** Пул принимает сид/генератор случайных чисел на вход: в обычной игре его передаёт [[Игровой цикл]], в серии прогонов — [[Стенд симуляции]]. Формулы и поведение внутри не меняются, но два прогона с одинаковым стартом и сидом дают побитово одинаковый результат.

## Контракт
- **Вход:** собственные текущие характеристики сущности-владельца (пул не отдельный сервис — это способность, которой обладает каждая сущность); текущий момент партии от [[Время]]; вызов тика от [[Игровой цикл]]; источник случайности снаружи; входящие явные события от других сущностей.
- **Выход:** факт в [[Журнал фактов]] на каждое сработавшее событие; изменение собственных характеристик; опционально — явное событие для другой сущности; опционально — новая дочерняя сущность, зарегистрированная в реестре родителя.
- **Владеет:** таблицей весов, модификаторов и эффектов своих событий; расписанием собственного тика; для сущностей, чьи события спавнят детей, — реестром живых дочерних сущностей.
- **Не знает:** о видимости в эфире и диапазонах (это [[Генератор эфира]]); о состоянии других сущностей напрямую, кроме как через входящие явные события — за исключением явно разрешённых внешних источников для модификаторов и параметров события. Сейчас таких три: [[Погода]] (погодозависимые события), Напряжённость [[Режиссёр]]а (события с тегом «агрессивное») и поле «место» [[Журнал фактов]] (выбор квадранта атаки у [[Фракции]]). Правило общее: пул может читать любой явно разрешённый внешний источник, если это зафиксировано в его контракте.

## Данные

**Строка события в пуле:**

| Поле | Тип / диапазон | Комментарий |
| :--- | :--- | :--- |
| id_события | строка, уникален в пуле сущности | — |
| базовый_вес | число | [нужно значение] по каждому событию |
| модификаторы | список (характеристика, коэффициент) | вес = базовый_вес + Σ коэффициент × значение; точная формула и нормализация — [нужно значение] |
| внешние_модификаторы | список (источник, коэффициент), может быть пуст | явно разрешённые внешние источники: Погода, Напряжённость |
| эффект_на_себя | список (характеристика, дельта), может быть пуст | как событие меняет характеристики владельца |
| шаблон_факта | по контракту записи [[Журнал фактов]] | тип_события, статус, место, тег_архетипа |
| событие_наружу | опционально: (кому, что) | явное событие для другой сущности |
| спавн | опционально: (тип дочерней сущности, диапазон стартовых характеристик) | только у событий, порождающих новую сущность |

**Расписание тика по типу сущности:**

| Тип сущности | Интервал тика | Значение |
| :--- | :--- | :--- |
| Город | [нужно значение] | — |
| Структура (Пост / База / Склад / Ретранслятор) | [нужно значение] | вероятно у каждого типа своё |
| Дочерняя сущность (Конвой и подобные) | [нужно значение] | вероятно чаще, раз в шаг по маршруту |
| Фракция | [нужно значение] | три типа, возможно одинаковый |

Все интервалы должны быть не меньше «шаг_лупа» из конфига [[Игровой цикл]], иначе луп будет проскакивать мимо срабатываний.

**Ограничение объёма характеристик:** 2–4 у обычной сущности, 7 — только у Города. Действует и для дочерних сущностей.

## Первый срез
У Склада в пуле одно событие — «родить конвой», вес растёт от характеристики Склада [нужно значение]. При срабатывании создаётся сущность Конвой с двумя характеристиками («пройдено» и «риск» — [нужно значение] точный состав) и собственным пулом из двух событий: «шаг по маршруту» (пишет факт «в пути», увеличивает «пройдено») и «прибыл» (терминальное, вес растёт от «пройдено», пишет факт, шлёт Городу «поставка_доставлена», удаляет Конвой из реестра Склада).

Признак готовности: Склад порождает Конвой; Конвой тикает свой пул самостоятельно; доходит до терминального события; всё различие между Городом, Складом и Конвоем в прогоне лежит в данных таблиц, а не в ветвлениях логики; повтор прогона с тем же сидом даёт тот же результат.

## Связи
- [[Игровой цикл]] — дёргает тик каждой сущности и передаёт источник случайности.
- [[Журнал фактов]] — шлёт событие: каждое сработавшее событие пишет факт с обязательным полем «место».
- [[Время]] — читает: текущий момент партии для сверки со своим расписанием тика.
- [[Погода]] — читает напрямую: погодозависимые события берут состояние погоды, минуя Журнал.
- [[Режиссёр]] — читает Напряжённость как внешний модификатор веса для событий с тегом «агрессивное».
- [[Стенд симуляции]] — передаёт сид для воспроизводимости серии.

## Открытые вопросы
- Точная формула веса (аддитивная или пороговая) и нормализация в вероятность выбора.
- Расписание тика по каждому типу сущности.
- Полный список типов событий по каждой сущности — контент.
- Точный вид добавки от Напряжённости к весу «агрессивных» событий.
