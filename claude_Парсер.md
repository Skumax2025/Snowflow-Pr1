# Парсер

## Суть
Парсер — единственная точка, где рапорт игрока встречается с LLM. Модель ничего не считает, только размечает текст: что игрок утверждает, каким тоном и не съехал ли он с темы. Дальше офлайн-код сверяет claims с [[Журнал фактов|Журналом фактов]] и пакует вердикт в одно явное событие [[Город]]у. Три входящих, два исходящих, единственный вызывающий [[Прокси к Gemini]].

## Как работает
1. [[Терминал]] шлёт событие «рапорт_отправлен» с сырым текстом. Парсер запускается на это событие синхронно, но сам вызов модели асинхронный — Терминал не ждёт ответа.
2. Перед вызовом Парсер собирает справочник имён: живые (Целостность > 0) [[Структуры]] с их квадрантами — читает у Структур; список типов [[Фракции|Фракций]] — читает у Фракций; формат и размер сетки квадрантов — из конфига партии ([[Игровой цикл]]). Это не состояние мира, а снимок словаря имён на момент вызова, чтобы модель не изобретала несуществующие места.
3. Текст + справочник уходят в [[Прокси к Gemini]] — ровно один вызов за сеанс связи. Ответ — JSON `claims[]` / `tone` / `offtopic`, настоящий или синтетический пустой при деградации; Парсер их не различает.
4. Каждый claim ищет совпадение в Журнале по (субъект, место, время) с допуском [нужно значение]. Три категории вердикта:
   - **правда** — субъект, место и время совпали с записью Журнала.
   - **ложь** — противоречит записи или события не было вовсе, при этом заявленная автором уверенность высокая.
   - **неточность** — противоречит записи или совпадение частичное, при этом уверенность автора низкая.
   Вместе с категорией Парсер отдаёт **id совпавшей записи Журнала** (или null). Определять, платил ли Город за этот факт раньше, — дело самого Города, у которого для этого есть дедуп-регистр. Парсер не обязан помнить историю прошлых рапортов и не помнит её.
5. Offtopic-блок (флаг + текст) уходит отдельным явным событием **«офтопик_обнаружен»** напрямую [[Фильтр аномалий]], минуя Город и минуя «вердикт_рапорта».
6. Claims-вердикты (список `{claim_id, категория, id_факта|null}`) и сырой `tone` пакуются в одно явное событие **«вердикт_рапорта»** → [[Город]]. Парсер сам не считает и не применяет дельты характеристик.
7. Парсер не читает [[Погода|Погоду]] и не занимается шторм-алиби. Эта проверка — целиком ручная работа игрока через [[Проверка сигнала]] и его собственную [[Карта|Карту]].
8. **Второй рапорт до обработки первого разрешён. [принято, делегировано]** Парсер стейтлесс, вызовы независимы, [[Город]] применяет вердикты в порядке прихода. Блокировать [[Терминал]] на время ответа значило бы вернуть состояние загрузки, от которого мы отказались.

## Контракт
- **Вход:** событие «рапорт_отправлен» (текст) от [[Терминал]]а.
- **Выход:**
  - явное событие «вердикт_рапорта» (список `{claim_id, категория, id_факта|null}` + сырой tone) → [[Город]];
  - явное событие «офтопик_обнаружен» (текст) → [[Фильтр аномалий]];
  - один вызов (текст рапорта + справочник имён) → [[Прокси к Gemini]] и приём его ответа.
- **Владеет:** логикой сопоставления claims с Журналом (алгоритм сверки, правило категорий по заявленной уверенности); фактом «один вызов на сеанс связи».
- **Не знает:** как Город считает дельты, риторическую насыщенность и дедуп; о существовании Газеты; реальный это ответ Прокси или синтетическая деградация; о Погоде и штормах; не хранит историю прошлых рапортов между сеансами.

## Данные
Схема ответа модели (claims/tone/offtopic) зафиксирована в мастер-конспекте, раздел 6.10 — здесь не дублируется.

**Таблица «Категории вердикта»:**

| Категория | Условие |
| :--- | :--- |
| правда | субъект + место + время совпали с записью Журнала |
| ложь | противоречит записи / события не было + высокая заявленная уверенность |
| неточность | противоречит записи / частичное совпадение + низкая заявленная уверенность |

Порог «высокая/низкая уверенность» и допуск по времени/месту при сверке — [нужно значение].

## Первый срез
Заглушка вместо [[Прокси к Gemini]] отдаёт фиксированный JSON на два claims (один совпадает с мок-записью Журнала, другой нет) + нейтральный tone + `offtopic=true` с текстом.

Прогон: в логе появляется одно событие «вердикт_рапорта» с двумя корректными категориями и корректными id_факта, и одно «офтопик_обнаружен» с текстом.

Признак готовности: категории совпадают с ожидаемыми вручную для обоих claims; offtopic ушёл отдельным событием, не утонул внутри вердикта; id совпавшего факта проставлен там, где совпадение было, и null там, где нет.

## Связи
- [[Терминал]] — принимает событие «рапорт_отправлен».
- [[Журнал фактов]] — читает: сверяет claims по (субъект, место, время).
- [[Структуры]] — читает: список живых структур и их квадрантов для справочника имён.
- [[Фракции]] — читает: список типов для справочника имён.
- [[Игровой цикл]] — читает: формат и размер сетки квадрантов из конфига партии.
- [[Прокси к Gemini]] — шлёт текст + справочник, единственный вызывающий; читает JSON.
- [[Город]] — шлёт «вердикт_рапорта».
- [[Фильтр аномалий]] — шлёт «офтопик_обнаружен».
- [[Погода]] — явно не связаны: шторм-алиби остаётся ручным.

## Открытые вопросы
- Точные допуски сверки claim↔Журнал по времени и месту.
- Порог заявленной уверенности, разделяющий «неточность» от «лжи».
- Есть ли у отдельных структур индивидуальные имена/номера для справочника, или он оперирует типом и квадрантом.
- Формат текста «офтопик_обнаружен»: весь рапорт целиком или только фрагмент, выделенный моделью.
- Реальная задержка ответа Gemini и как она ощущается игроком, если он успел уйти с терминала.
