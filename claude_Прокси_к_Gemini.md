# Прокси к Gemini

## Суть
Единственная точка, где игра говорит с внешним LLM. Serverless-функция на Vercel: прячет ключ, ограничивает частоту вызовов и гарантирует, что падение или исчерпание квоты Gemini не останавливает игру. Любой сбой полностью гасится здесь — наружу всегда уходит валидный по форме разбор, вызывающая сторона не отличает настоящий ответ от подделки.

## Как работает
1. Принимает от [[Парсер]]а ровно один вызов на сеанс связи: текст рапорта + справочник имён (квадранты, живые структуры, типы фракций).
2. Строит промпт (системный промпт + текст + справочник), обращается к Gemini API (Flash/Flash-Lite, бесплатный тариф — см. мастер-конспект 3.2).
3. Валидирует ответ на соответствие JSON-схеме claims/tone/offtopic. Невалидный JSON, таймаут, ошибка квоты или сети, недействительный ключ — всё это один класс исходов: **деградация**.
4. При деградации отдаёт синтетический «пустой» разбор: `claims=[]`, `tone` — нейтральные дефолты, `offtopic=false`. По форме неотличим от настоящего ответа.
5. Превышение рейт-лимита по IP обрабатывается так же — тем же пустым разбором, не отдельным кодом ошибки.
6. Логирует факт и причину деградации только на сервере, для отладки. Это не игровые данные и не событие для других систем.
7. Ключ Gemini живёт только в переменных окружения Vercel, никогда не попадает в код, уходящий в браузер.
8. Тот же паттерн рейт-лимита по IP применён на втором сетевом эндпоинте проекта — записи офтопика в [[Фильтр аномалий]]. Реализация общая, конкретные лимиты у каждого свои.

## Контракт
- **Вход:** текст рапорта + справочник имён — от [[Парсер]]а, один вызов на сеанс связи.
- **Выход:** JSON строго по схеме claims/tone/offtopic — настоящий разбор или синтетический пустой при любом сбое, без различия в форме.
- **Владеет:** ключом API (в окружении, не в состоянии игры); системным промптом; JSON-схемой валидации; рейт-лимитом по IP; собственным серверным логом деградаций.
- **Не знает:** о [[Терминал]]е, [[Время]]ни, [[Генератор]]е, [[Город]]е, [[Журнал фактов|Журнале фактов]] — весь контекст приходит только как справочник имён, не состояние мира; не знает, что происходит с её ответом дальше.

## Первый срез
Захардкоженный текст рапорта → реальный вызов Gemini с минимальным системным промптом → валидный JSON доходит до лога без искажений. Отдельно: подмена ключа на заведомо неверный → наружу уходит пустой разбор той же формы, не исключение. Отдельно: превышение рейт-лимита с одного IP → тот же пустой разбор.

Признак готовности: успешный и три вида сбойных прогонов дают структурно одинаковый по форме ответ, различаются только содержимым claims/tone.

## Связи
- [[Парсер]] — единственный вызывающий; получает результат разбора в любом случае, включая деградацию.
- [[Фильтр аномалий]] — не связаны по данным, но переиспользуют один и тот же паттерн рейт-лимита по IP на своём эндпоинте.

## Открытые вопросы
- Таймаут запроса и значение рейт-лимита.
- Точные нейтральные значения tone для пустого разбора.
- Конкретная модель (Flash vs Flash-Lite) и лимиты на момент деплоя — перепроверить, как отмечено в 3.2.
- Содержимое системного промпта.
- Формат и место серверного лога деградаций.
